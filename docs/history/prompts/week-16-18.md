## How you work: the loop
Repeat until the stop condition holds. Do not stop early, and do not call a partial run a success.

1. Read `reports/week16-18_progress.md` and `git log --oneline -15`. In iteration 1, create the
   branch `week-16-18` from `main` after merging `origin/main` (checklist item 9 needs the
   daily-prediction commits), and create the progress file with §0's answers. Pick the next
   unfinished work: a wave of parallel subtasks (§5) or a deliverable you do yourself.
2. Delegate it, or implement it yourself, with tests.
3. **Verify it yourself; never take a report on trust.** When a subagent says it is done, you
   review its diff (§5 review list), merge its worktree branch, and rerun its Done-when checks
   yourself in the main tree. A subagent's "all green" is not evidence. Order:
   - the deliverable's **Done when** checks (§4), each an automated test or a script under
     `scripts/checks/`, never checked by eye (screenshots are reviewed by you *and* checked by
     script);
   - the fast gate every iteration: `SKIP="7 8 10 12 13 15 16 18 20 21 22 23 24 25 26 30 31 35
     36 37 38 39 41 45 46 50 51" bash scripts/checklist.sh`, plus every §7 item the change
     touched;
   - the **whole** §7 checklist when a deliverable is finished, before you mark it done (see the
     load guard below).
4. If anything is red, find the root cause and fix it, or send the subagent back with the exact
   failing output and what you think the cause is. Then go back to step 3. Never weaken, skip,
   `xfail` or delete a check. Never raise a tolerance without a written justification in the
   progress file, and that justification must not use the observed failing numbers as the reason.
5. When it is green: make a small commit, then append `iteration N | deliverable | checks run |
   result | commit` to the progress file. Record the pre-registration shas on their own lines:
   `VERDICT <sha>`, `VALIDATION <sha>`, `TEST <sha>` (M5 once forgot `TEST`, which made its order
   check red).
6. **Stop condition:** L0–L12 are done **and** the full §7 checklist passes top to bottom in one
   run with no edits in between. The only items allowed to stay red are 22 and 25 (the known M2
   limitations) and the L-h gate *outcome*, each with its evidence. If the owner chooses a
   fast-gate record instead, record exactly which items ran on which HEAD and say so in the
   closeout.

Guards:

  the progress file, re-read the code and the data, then fix the cause.
- **Iteration budget: 35.** At the end of iteration 35, stop anyway. Write the closeout with
  status `INCOMPLETE`, each red check with its last error, and what you would try next.

- **Quiet machine for timed checks.** Before any full checklist run or timed backtest, check CPU

  with their command lines. Other projects' jobs have run on this machine. Never kill a process
  you did not start: record it and ask the owner whether to wait, run anyway, or run a fast gate.
  No subagent may run during a timed run.
- **DuckDB is single-writer.** Only you (the orchestrator) run commands that touch `data/`.
- **Network:** none is expected. The EuroLeague API is unofficial and ESAKE is throttled
  (≥ 2 s): if a fact needs a fetch, cache it under `data/raw/`, once.
- **Local data restore:** plain `eurohoops ingest` re-stages only 2023+; before any `build` run
  `ingest --from-season 2007` (cache-only), then `build` and `stints --mart`. Checklist items 11,

- **Windows shell:**
  - `bash` resolves to WSL here. Run `scripts/checklist.sh` with Git Bash, or through the Bash
    tool, with Git's `usr/bin` first on PATH.
  - MLflow rejects Git Bash `/tmp` paths in `sqlite:///` URIs; build URIs with `cygpath -m`.

  - Git Bash mangles `robocopy /E`; run robocopy from PowerShell (exit 1 = copied).
- **Resumability:** the progress file and the commits are your memory. After any interruption,

### L1: Projection core (wave 1, subagent A)
`models/projection.py`: `project(history, target, variant, params) -> Projections` (per player,
per L-b stat: mean, lo80, hi80, exposure, flags) with the L-c method, decay, empirical-Bayes
shrinkage per stat, and hooks for aging (L2) and translation (M4 factors passed in, not fitted).
**Done when:**
- on 200 synthetic leagues with known true rates, 80% intervals cover 77–83% (bound from the
  number of synthetic players, written in the test);
- shrinkage weight → 1 as exposure → ∞ and → 0 as exposure → 0 (property test);
- a player with one season and no prior gets the league mean ± the prior SD;
- leakage: rows at or after the cutoff change nothing.

### L2: Aging curve (wave 1, subagent B)
`models/aging.py`: `aging_curve(history, cutoff) -> AgingCurve` (per stat, delta by age, with SE)

**Done when:** a synthetic population with a planted curve and planted survivor dropout recovers

seasons only) to set how much of the gap is expected to persist.
**Done when:** the labels follow from the formula on hand-built players; a backtest helper shows,
on synthetic data with planted true skill, that "likely regression" players regress more next
season than "likely real" ones; leakage test.

**Done when:** a self-retrieval test: on fixtures, a player's season s finds his own season s+1
